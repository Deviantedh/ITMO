### Требования спецификации Варианта № 5 («Кодовый замок»):
* **Энергонезависимое хранилище:** Мастер-пароль замка должен постоянно храниться в энергонезависимой памяти EEPROM микросхемы MCP79411. При подаче питания пароль автоматически считывается из памяти; при смене пароля новое значение надежно прошивается в ячейки EEPROM.
* **Динамическая длина пароля:** Поддержка паролей длиной от 1 до 16 символов (заводской пароль по умолчанию при первом старте чистой памяти — `1234`).
* **Визуализация на OLED-экране:** В реальном времени отображать вводимую комбинацию (в виде звездочек или символов маски) и текущее состояние системы:

  * `BLOCKED` — защитная блокировка на 5 секунд после 3 ошибок подряд (мигание красного светодиода VD7).
* **Клиентское приложение для ПК:**
  * Графический интерфейс пользователя (GUI), разработанный на языке Python (Tkinter). Консольный ввод в виде командной строки строго запрещён заданием!
  * Автоматическая посылка команды типа «пинг» (`PING\n`) сразу после открытия COM-порта для проверки доступности стенда.
  * Форма ввода пароля для открытия замка.
  * Форма задания нового пароля для записи в EEPROM.
  * Автоматическое ведение файла журнала на диске ПК с фиксацией точных меток времени всех транзакций по UART.

## 2. Физический и канальный уровень интерфейса I2C

**I2C (Inter-Integrated Circuit)** — это синхронный последовательный полудуплексный двунаправленный интерфейс обмена данными, разработанный фирмой Philips (ныне NXP) в начале 1980-х годов для связи микросхем на одной печатной плате по двум проводникам.

```
+3.3V ----+---------------+-------------------+
          | R_pull-up     | R_pull-up         |
         [4.7k]          [4.7k]               |
          |               |                   |
          +-------+-------(-------------------+--- SCL (Serial Clock)
          |       |       |                   |
          |       +-------+-------------------+--- SDA (Serial Data)
          |       |       |                   |
     +----+-------+--+ +--+-------+----+ +----+-------+----+
     |    SCL   SDA  | |  SCL   SDA    | |    SCL   SDA  |
     |   STM32F427   | |    SSD1306    | |    MCP79411   |
     |   (Master)    | | (Slave: 0x78) | | (Slave: 0xAE) |
     +---------------+ +---------------+ +---------------+
```

### 2.1. Принцип двухпроводной шины и схемотехника Open-Drain
Интерфейс использует всего две сигнальные линии:
1. **SCL (Serial Clock Line)** — линия синхросигнала, задающая темп передачи битов. В стандартных сценариях формируется ведущим узлом (Master).
2. **SDA (Serial Data Line)** — двунаправленная линия передачи адреса, команд и данных.

Выходные каскады всех подключённых к шине контроллеров и микросхем выполнены по схеме с **открытым стоком (Open-Drain)** у полевых транзисторов (или открытым коллектором у биполярных):
* Внутри микросхемы выходной транзистор может лишь соединить линию с общим проводом (землей, GND), установив на ней потенциал логического нуля ($0\text{ В}$).
* Микросхемы **физически не способны выдать активную единицу (+3.3 В)**: верхний транзистор Push-Pull каскада отсутствует.
* Высокий логический уровень формируется исключительно внешними резисторами подтяжки ($R_{pull-up}$ номиналом $2.2 \dots 10\text{ кОм}$), когда транзисторы всех устройств закрыты (отпущены).

### 2.2. Логика монтажного «И» (Wired-AND) и аппаратный арбитраж
Благодаря схемотехнике открытого стока линия I2C работает по логике **«монтажного И»**:
$$\text{Line State} = D_1 \ \& \ D_2 \ \& \ \dots \ \& \ D_n$$
Если хотя бы одно устройство притягивает линию к нулю, на всей шине устанавливается низкий уровень. Высокий уровень возможен только тогда, когда **все без исключения** устройства отпустили линию.

Это дает два фундаментальных преимущества:
1. **Исключение короткого замыкания:** Даже если ведущий передает $0$, а ведомый пытается выдать $1$, ток через резистор подтяжки ограничен несколькими миллиамперами ($I = \frac{3.3\text{ В}}{4.7\text{ кОм}} \approx 0.7\text{ мА}$), и транзисторы не сгорают.
2. **Аппаратный побитовый арбитраж шины:** Если два ведущих одновременно пытаются захватить шину, они начинают передачу и синхронно считывают состояние линии SDA на каждом такте SCL.
   * Если узел выдал $1$ (отпустил ключ), но считывает с шины $0$ (потому что другой узел открыл ключ и притянул линию к земле), этот узел фиксирует потерю арбитража (**Arbitration Lost, флаг ARLO в STM32**).
   * Проигравший узел немедленно отключает передатчик данных SDA, не ломая кадр конкурента, и переходит в режим ожидания. Выигрывает узел, передающий адрес с большим числом нулей.

### 2.3. Базовые состояния шины: START, STOP, Repeated START
В состоянии покоя (Idle) обе линии шины находятся в высоком уровне: $\text{SCL} = 1, \text{SDA} = 1$.

```
SCL:  ~~~~\______/~~~~~\______/~~~~~\______/~~~~~~~
SDA:  ~~~~~~\______/~~~~~\______________/~~~~~~~~~~
          ^                            ^
        START                         STOP
```

1. **Условие СТАРТ (START condition / S):**
   Формируется ведущим. Это переход линии SDA из высокого уровня в низкий при сохранении **высокого уровня** на линии SCL.
2. **Условие СТОП (STOP condition / P):**
   Формируется ведущим для освобождения шины. Это переход линии SDA из низкого уровня в высокий при **высоком уровне** на линии SCL.
3. **Повторный старт (Repeated START / Sr):**
   Формирование нового условия START без предварительной генерации STOP. Позволяет ведущему сменить направление передачи (например, перейти от записи адреса регистра к чтению данных) без освобождения шины, исключая вмешательство других ведущих устройств.

### 2.4. Передача битов, правило валидности данных и 9-й такт ACK/NACK
* **Правило стабильности данных (Data Validity):**
  Состояние линии SDA разрешено изменять **только тогда, когда на линии SCL низкий уровень**. Во время высокого уровня SCL сигнал на линии SDA обязан оставаться неизменным. Любое изменение SDA при высоком SCL воспринимается аппаратными узлами как условие START или STOP!

```
SCL:        ________/~~~~~~~~~~\________
SDA:   ... X========<  VALID   >========X ...
            Изменение          Изменение
            разрешено          разрешено
```

* **Кадр передачи байта:**
  Данные передаются пакетами по **8 бит, старшим битом вперед (MSB First)**.
* **9-й такт подтверждения (ACK / NACK):**
  После каждых 8 бит данных ведущий генерирует 9-й такт синхросигнала на линии SCL. В течение этого такта передатчик освобождает линию SDA:
  * **ACK (Acknowledge, 0):** Приемник притягивает линию SDA к земле. Это подтверждает успешный прием байта.
  * **NACK (Not Acknowledge, 1):** Линия SDA осталась в высоком уровне (никто не притянул её к нулю). Это сигнализирует либо об отсутствии устройства с данным адресом, либо о занятости ведомого (например, цикл записи EEPROM), либо о завершении операции чтения (когда ведущий читает последний байт и специально не выставляет ACK перед отправкой STOP).

### 2.5. Удержание линии тактирования (Clock Stretching)
Если ведомое устройство (Slave) не успевает обработать принятый байт (например, микроконтроллеру требуется время на обработку прерывания или вычисление контрольной суммы), оно имеет право аппаратно притянуть линию SCL к нулю после приема ACK.
Ведущий узел, пытаясь перевести SCL в высокий уровень, считывает фактическое состояние линии. Видя $0$, ведущий приостанавливает свой таймер и терпеливо ждет, пока ведомый отпустит SCL. Это встроенный механизм аппаратного управления потоком данных.

### 2.6. Адресация ведомых: 7-битный и 8-битный форматы, бит R/W#
Каждое ведомое устройство на шине имеет уникальный аппаратный адрес. В большинстве современных микросхем используется **7-битная адресация** (значения от `0x08` до `0x77`; диапазоны `0x00..0x07` и `0x78..0x7F` зарезервированы для специальных системных команд: General Call, 10-bit address header, High-Speed mode).

При передаче по шине 7-битный адрес упаковывается в 8-битный первый байт транзакции со сдвигом на 1 бит влево:
$$\text{Address Byte (8-bit)} = (\text{7-bit Address} \ll 1) \ | \ \text{R/W\#}$$

* Младший нулевой бит ($b_0$) задает направление транзакции:
  * $b_0 = 0$ — **Запись (Write)**: ведущий передает данные в ведомый узел.
  * $b_0 = 1$ — **Чтение (Read)**: ведущий считывает данные из ведомого узла.

> **Важно помнить на защите:** Контроллер дисплея SSD1306 имеет 7-битный адрес `0x3C`. В 8-битном формате для записи он передается как `0x78` ($0x3C \times 2 = 0x78$), а для чтения — `0x79`. Библиотека STM32 HAL принимает в функциях именно 8-битное значение адреса со сдвигом!

## 3. Аппаратный контроллер I2C в микроконтроллерах STM32F427

Микроконтроллер STM32F427VIT6 оснащен 3 независимыми аппаратными блоками I2C (I2C1, I2C2, I2C3), поддерживающими режимы Master/Slave, мультимастерную работу, 7- и 10-битную адресацию, режимы Standard Mode (до 100 кГц) и Fast Mode (до 400 кГц), а также протоколы SMBus 2.0 / PMBus.

### 3.1. Архитектура модуля I2C1 на шине APB1
Периферийный блок I2C1 подключен к системной шине **APB1 (Advanced Peripheral Bus 1)**.
* Максимальная тактовая частота шины APB1 в STM32F427 составляет $f_{PCLK1} = 42\text{ МГц}$ (при частоте ядра процессора 168 МГц).
* Выводы контроллера соединяются с матрицей портов ввода-вывода через мультиплексор альтернативных функций:
  * Вывод `PB8` конфигурируется как `AF4` (`I2C1_SCL`);
  * Вывод `PB9` конфигурируется как `AF4` (`I2C1_SDA`).
  * Режим GPIO: **Open-Drain, High Speed, без внутренней подтяжки (или с Pull-Up)**.

```
       APB1 Bus (42 MHz)
              |
   +----------v-----------------------------------------------+
   |                      I2C1 Module                         |
   |                                                          |
   |  +------------+   +------------+   +------------------+  |
   |  |  CR1, CR2  |   |  SR1, SR2  |   |  CCR, TRISE      |  |
   |  | (Control)  |   |  (Status)  |   |  (Clock Config)  |  |
   |  +------------+   +------------+   +------------------+  |
   |                                                          |
   |  +------------+   +------------+   +------------------+  |
   |  | Shift Reg. |<->|  Data (DR) |   | Noise Filters    |  |
   |  +------------+   +------------+   +------------------+  |
   +----------|----------------------------------|------------+
              |                                  |
          PB8 (SCL)                          PB9 (SDA)
```

### 3.2. Регистры управления и статуса: CR1, CR2, SR1, SR2, OAR1/2

| Регистр | Название | Ключевые биты и назначение |
|---|---|---|
| **I2C_CR1** | Control Register 1 | **PE** (Peripheral Enable — включение блока), **START** (генерация условия старт), **STOP** (генерация стопа), **ACK** (автоматическая выдача ACK при приеме), **POS** (позиция ACK при 2-байтном приеме), **SWRST** (программный сброс блока при зависании шины). |
| **I2C_CR2** | Control Register 2 | **FREQ[5:0]** (частота шины APB1 в МГц, от 2 до 50; для 42 МГц записывается число 42), **ITERREN** (разрешение прерываний ошибок), **ITEVTEN** (разрешение прерываний событий шины), **ITBUFEN** (разрешение прерываний буферов TxE/RxNE), **DMAEN** (включение DMA). |
| **I2C_SR1** | Status Register 1 | **SB** (Start Bit — условие старт успешно сформировано), **ADDR** (Address Sent/Matched — адрес передан и получен ACK), **BTF** (Byte Transfer Finished — байт полностью передан из сдвигового регистра), **RxNE** (приемный буфер не пуст), **TxE** (передающий буфер пуст), **BERR** (Bus Error — помеха на шине), **ARLO** (Arbitration Lost — проигрыш арбитража), **AF** (Acknowledge Failure — получен NACK), **OVR** (Overrun — переполнение буфера). |
| **I2C_SR2** | Status Register 2 | **MSL** (Master/Slave: 1 — режим ведущего, 0 — ведомый), **BUSY** (1 — шина занята передачей), **TRA** (1 — передатчик, 0 — приемник). Чтение SR2 сразу после SR1 служит аппаратным механизмом сброса флага ADDR! |
| **I2C_CCR** | Clock Control | **F/S** (0 — Standard Mode 100 кГц, 1 — Fast Mode 400 кГц), **DUTY** (коэффициент заполнения в Fast Mode: 0 — 50%, 1 — 16/9), **CCR[11:0]** (значение делителя тактовой частоты). |
| **I2C_TRISE** | Rise Time | Максимальное время нарастания фронта сигнала в тактах шины APB1. Служит для ограничения искажений сигналов при емкостной нагрузке. |

### 3.3. Формирование тактовой частоты: регистры CCR и TRISE (расчёт для Standard Mode)
Период одного такта шины APB1 при частоте $f_{PCLK1} = 42\text{ МГц}$:
$$T_{PCLK1} = \frac{1}{42 \times 10^6\text{ Гц}} \approx 23.81\text{ нс}$$

#### Расчёт регистра CCR для Standard Mode (100 кГц):
В стандартном режиме скважность строго равна 2 (длительность высокого уровня равна длительности низкого уровня):
$$T_{high} = T_{low} = \frac{T_{SCL}}{2} = \frac{10\text{ мкс}}{2} = 5\text{ мкс} = 5000\text{ нс}$$
Формула из Reference Manual STM32F4:
$$T_{high} = CCR \times T_{PCLK1} \implies CCR = \frac{T_{high}}{T_{PCLK1}} = \frac{5000\text{ нс}}{23.81\text{ нс}} \approx 210 \quad (\text{hex: } 0x00D2)$$

#### Расчёт регистра TRISE:
В спецификации I2C максимальное время нарастания фронта ($t_r$) для Standard Mode составляет $1000\text{ нс}$.
Формула расчёта:
$$TRISE = \frac{t_{r\_max}}{T_{PCLK1}} + 1 = \frac{1000\text{ нс}}{23.81\text{ нс}} + 1 = 42 + 1 = 43 \quad (\text{hex: } 0x002B)$$

### 3.4. Аналоговый и цифровой фильтры шумов
На реальной печатной плате из-за паразитных емкостей дорожек и электромагнитных наводок на линиях SCL и SDA могут возникать короткие высокочастотные всплески напряжения (glitches).
В контроллере I2C микроконтроллера STM32F4 встроен **аппаратный аналоговый фильтр (Analog Noise Filter)**:
* Активируется функцией: `HAL_I2CEx_ConfigAnalogFilter(&hi2c1, I2C_ANALOGFILTER_ENABLE);`
* Аппаратно подавляет любые выбросы и помехи длительностью до **50 нс**, предотвращая ложные срабатывания детекторов START/STOP.
* Дополнительно доступен цифровой фильтр на базе счетчика тактов $T_{PCLK1}$.

### 3.5. Методы ввода-вывода I2C: опрос (Polling), прерывания (IT), DMA
1. **Программный опрос флагов (Polling, блокирующий режим):**
   * Вызов `HAL_I2C_Master_Transmit(&hi2c1, DevAddress, pData, Size, Timeout)`.
   * Процессор в плотном цикле ожидает взвода флагов `SB`, `ADDR`, `TxE` в регистрах `SR1/SR2`.
   * *Плюсы:* предельная простота отладки, идеально подходит для начальной инициализации дисплея.
   * *Минусы:* процессор полностью простаивает во время передачи. При передаче кадра OLED (1024 байта на 100 кГц) ядро блокируется на **~100 миллисекунд**!
2. **Аппаратные прерывания (Interrupts, неблокирующий режим):**
   * Вызов `HAL_I2C_Master_Transmit_IT(...)`.
   * По завершении передачи каждого байта генерируется прерывание `I2C1_EV_IRQHandler` (Event) или `I2C1_ER_IRQHandler` (Error).
   * Позволяет выполнять прикладной код суперцикла параллельно с передачей данных.
3. **Прямой доступ к памяти (DMA — Direct Memory Access):**
   * Контроллер DMA самостоятельно перекачивает 1024 байта кадрового буфера из SRAM в регистр `I2C_DR` вообще без участия процессорного ядра.

### 3.6. Разница между функциями HAL_I2C_Master_Transmit и HAL_I2C_Mem_Write
* `HAL_I2C_Master_Transmit(hi2c, DevAddress, pData, Size, Timeout)`:
  Генерирует START, передает байт адреса ведомого устройства (`DevAddress | 0`), после чего последовательно выталкивает массив `pData`. Подходит для дисплея SSD1306.
* `HAL_I2C_Mem_Write(hi2c, DevAddress, MemAddress, MemAddSize, pData, Size, Timeout)`:
  Специализированная функция для работы с микросхемами памяти и регистровыми чипами (EEPROM, RTC, акселерометры). Сначала передает адрес устройства, затем передает **внутренний адрес регистра/ячейки памяти (`MemAddress`)** разрядностью 1 или 2 байта (`MemAddSize`), и лишь затем начинает передавать полезную нагрузку `pData`.

### 4.2. Проблема конкурентного доступа к общей шине I2C и методы её решения
Все перечисленные выше устройства физически висят на **одних и тех же проводниках PB8 и PB9**.
* Если прошивка попытается начать опрос памяти EEPROM или клавиатуры в тот момент, когда контроллер I2C еще не закончил передачу 1024 байт кадра в дисплей, возникнет аппаратный конфликт: шина окажется занята (`HAL_BUSY`), и вызов завершится ошибкой.
* **Решения:**
  1. *В кооперативном суперцикле (как в нашей Лаб 3):* Строгая последовательная диспетчеризация. Обновление экрана `oled_UpdateScreen()` инициируется только тогда, когда замок сменил состояние или изменилась маска пароля, а обращение к EEPROM происходит атомарно при старте и по факту ввода нового пароля.
  2. *В операционной системе реального времени (FreeRTOS, Лаб 4):* Защита шины I2C с помощью **мьютекса (Mutex)**. Любая задача (`Task_OLED`, `Task_EEPROM`), прежде чем выполнить транзакцию, обязана захватить мьютекс шины через `xSemaphoreTake()`, а по завершении — освободить через `xSemaphoreGive()`.

## 5. Графический OLED-дисплей WEO012864D (контроллер SSD1306)

### 5.1. Физический принцип OLED и преимущества перед ЖК (LCD)
В модуле WEO012864D используется матрица на органических светодиодах (Organic Light Emitting Diode):
* **Собственное свечение:** Каждый пиксель — это микроскопический органический светодиод. В отличие от жидкокристаллических дисплеев (TFT/LCD), здесь полностью отсутствует задняя лампа подсветки.
* **Истинный черный цвет и бесконечный контраст:** Черный пиксель — это полностью выключенный светодиод с нулевым энергопотреблением.
* **Углы обзора:** Достигают практически $180^\circ$ без искажения цветов и падения яркости.
* **Быстродействие:** Время отклика субмикросекундное (картинка не «мажется» на морозе в отличие от жидких кристаллов).

### 5.2. Структура видеопамяти GDDRAM (1024 байта, 8 страниц по 128 столбцов)
Встроенная статическая видеопамять **GDDRAM (Graphic Display Data RAM)** контроллера SSD1306 имеет размер:
$$\text{Размер GDDRAM} = 128 \text{ столбцов} \times 64 \text{ строки} = 8192 \text{ бит} = 1024 \text{ байта}$$

Память организована в виде **8 горизонтальных страниц (Page 0 .. Page 7)**:
* Каждая страница содержит 128 столбцов (Segment 0 .. Segment 127).
* В каждой странице по вертикали располагается 8 строк пикселей.
* **Байты ориентированы строго вертикально!**
  * Младший бит $D_0$ кодирует верхний пиксель страницы.
  * Старший бит $D_7$ кодирует нижний пиксель страницы.

```
       Column 0       Column 1               Column 127
     +--------------+--------------+ ... +--------------+
     | D0           | D0           |     | D0           |  Row 0
     | D1           | D1           |     | D1           |  Row 1
PAGE0| ...          | ...          |     | ...          |  ...
     | D7           | D7           |     | D7           |  Row 7
     +--------------+--------------+ ... +--------------+
     | D0           | D0           |     | D0           |  Row 8
PAGE1| ...          | ...          |     | ...          |  ...
     | D7           | D7           |     | D7           |  Row 15
     +--------------+--------------+ ... +--------------+
       ...            ...                   ...
     +--------------+--------------+ ... +--------------+
PAGE7| D0 ... D7    | D0 ... D7    |     | D0 ... D7    |  Rows 56..63
     +--------------+--------------+ ... +--------------+
```

### 5.3. Горизонтальный режим адресации и формат команд/данных (Control Byte)
При передаче пакета в SSD1306 первым байтом после адреса шины `0x78` всегда передается **байт управления (Control Byte)**:
* Бит $C_0$ (Continuation): если $0$, то все последующие байты до конца транзакции интерпретируются как полезная нагрузка.
* Бит $D/\bar{C}$ (Data / Command):
  * $D/\bar{C} = 0$ — передаются **команды настройки** (байт управления `0x00`);
  * $D/\bar{C} = 1$ — передаются **видеоданные в память GDDRAM** (байт управления `0x40`).

Контроллер SSD1306 поддерживает 3 режима адресации:
1. *Page Addressing Mode* (по умолчанию): после записи байта инкрементируется столбец ($0 \dots 127$), а по достижении правого края адрес зацикливается в начало той же страницы.
2. *Horizontal Addressing Mode* (используется в нашей прошивке, команда `0x20` $\rightarrow$ `0x00`): после 127-го столбца счетчик автоматически сбрасывается в 0-й столбец, а номер страницы инкрементируется ($Page 0 \rightarrow Page 1 \dots \rightarrow Page 7$). Это позволяет обновить весь экран (все 1024 байта) за одну непрерывную I2C-транзакцию без повторной отправки координат!

### 5.4. Организация программного кадрового буфера в ОЗУ микроконтроллера
Так как контроллер SSD1306 не поддерживает чтение отдельных битов по I2C (только запись), прямая отрисовка отдельных пикселей на экране невозможна: чтобы зажечь один пиксель $(x, y)$, необходимо знать состояние остальных 7 пикселей того же вертикального байта.

Поэтому в оперативной памяти микроконтроллера STM32 выделяется **локальный кадровый буфер (Frame Buffer)**:
```c
static uint8_t SSD1306_Buffer[1024]; // 128 * 64 / 8
```
* Любые графические примитивы (рисование точки, линии, прямоугольника, рендеринг шрифтов) модифицируют только локальный массив `SSD1306_Buffer` в сверхбыстрой оперативной памяти SRAM процессора.
* Функция зажжения пикселя $(x, y)$:
  $$\text{Byte Index} = x + \left(\frac{y}{8}\right) \times 128, \quad \text{Bit Mask} = 1 \ll (y \pmod 8)$$
  ```c
  void oled_DrawPixel(uint8_t x, uint8_t y, OLED_COLOR color) {
      if (x >= 128 || y >= 64) return;
      if (color == OLED_COLOR_WHITE) {
          SSD1306_Buffer[x + (y / 8) * 128] |= (1 << (y % 8));
      } else {
          SSD1306_Buffer[x + (y / 8) * 128] &= ~(1 << (y % 8));
      }
  }
  ```
* Когда изображение сформировано, вызывается функция `oled_UpdateScreen()`, которая единой потоковой транзакцией отправляет 1024 байта на контроллер дисплея.

### 5.5. Растровые шрифты (7×10, 11×18) и алгоритм вывода символов
Символы хранятся в Flash-памяти в виде битовых растровых матриц:
* Шрифт **Font 7×10**: каждый глиф описывается 10 словами по 16 бит (или массивом байт), ширина знака 7 точек, высота 10 точек. Используется для служебных надписей и статусных строк.
* Шрифт **Font 11×18**: ширина 11 точек, высота 18 точек. Обеспечивает отличную читаемость крупного текста на расстоянии (использован для отображения маски пароля `****`).
* Алгоритм посимвольной печати `oled_WriteChar(char ch, FontDef Font, OLED_COLOR color)` последовательно считывает биты строки за строкой и вызывает `oled_DrawPixel(x + i, y + j, color)`.

## 6. Энергонезависимая память EEPROM (микросхема MCP79411)

### 6.1. Принцип хранения заряда в ячейках с плавающим затвором
Память **EEPROM (Electrically Erasable Programmable Read-Only Memory)** построена на базе МОП-транзисторов с **плавающим затвором (Floating Gate)**:
* Плавающий затвор полностью изолирован сверхтонким слоем диэлектрика (оксид кремния $SiO_2$).
* При записи на управляющий затвор подается повышенное напряжение (формируется встроенным умножителем напряжения — Charge Pump), и электроны за счет квантовомеханического **туннелирования Фаулера-Нордгейма** преодолевают потенциальный барьер и накапливаются на плавающем затворе.
* Накопленный отрицательный заряд сдвигает пороговое напряжение открытия транзистора. При чтении этот сдвиг детектируется как логический $0$ или $1$.
* За счет изоляции диэлектриком электроны остаются в ловушке десятилетиями даже при полном отключении источника питания (гарантированное время хранения данных микросхемы MCP79411 — **более 100 лет**, ресурс циклов перезаписи — **более 1 000 000 раз**).

### 6.2. Организация памяти: 128 байт, страничная структура
В микросхеме MCP79411 под энергонезависимую память EEPROM выделен блок объемом **1 Кбит (128 байт)**:
* Пространство адресов: от `0x00` до `0x7F`.
* Память разбита на **16 страниц по 8 байт** (Page 0: 0x00..0x07, Page 1: 0x08..0x0F и т.д.).
* *Ограничение страничной записи (Page Boundary Wrap-Around):* при пакетной записи более 8 байт подряд внутренний счетчик адреса инкрементируется только в пределах текущей страницы. При переходе границы страницы счетчик циклически сбрасывается в начало этой же страницы, перезаписывая ранее внесенные данные! Поэтому надежнее всего программировать память побайтово либо строго контролировать границы страниц.

### 6.3. Технологический цикл записи ($t_{WC} = 5\text{ мс}$) и пауза программирования
В отличие от оперативной памяти SRAM, где запись происходит за один такт шины (наносекунды), физический процесс туннелирования зарядов в плавающий затвор требует значительного времени:
$$\text{Write Cycle Time } (t_{WC}) \le 5\text{ мс}$$

* В течение этих 5 миллисекунд внутренний контроллер памяти физически занят процессом программирования высоковольтными импульсами.
* Если во время цикла $t_{WC}$ попытаться отправить новый запрос по I2C, микросхема MCP79411 **не выставит подтверждение ACK (выдаст NACK)**.
* **В прошивке реализовано правило:** после записи каждого байта вызывается программная выдержка времени:
  ```c
  HAL_Delay(6); // Гарантированное завершение цикла t_WC (5 мс + запас 1 мс)
  ```
* Альтернативный метод — **Acknowledge Polling**: циклическая посылка стартового адресного байта до тех пор, пока память не ответит ACK.

### 6.4. Формат хранения пароля: сигнатура инициализации, длина и данные
Для предотвращения чтения «мусора» из неинициализированной памяти на заводе (где все байты равны `0xFF`), в прошивке реализован структурированный формат хранения:

| Адрес EEPROM | Поле | Значение по умолчанию | Назначение |
|:---:|---|:---:|---|
| `0x00` | **Сигнатура (Magic Byte)** | `0xA5` | Маркер инициализированной памяти. Если по адресу `0x00` считано не `0xA5`, прошивка понимает, что это первый старт стенда, и автоматически записывает заводские параметры. |
| `0x01` | **Длина пароля ($N$)** | `4` | Фактическая длина активного пароля (от 1 до 16 байт). |
| `0x02` .. `0x11` | **Символы пароля** | `'1', '2', '3', '4'` | Байтовый массив символов мастер-пароля. |

## 7. Аппаратные таймеры микроконтроллеров STM32

### 7.1. Базовая структура аппаратного таймера: PSC, CNT, ARR
Аппаратный таймер микроконтроллера STM32 представляет собой независимый цифровой счетчик с программируемой базой времени.

```
                  +-----------------------------+
f_CK_PSC ------> | Предделитель (PSC, 16 бит)  |
(APB Clock)       +--------------|--------------+
                                 | f_CNT = f_CK_PSC / (PSC + 1)
                  +--------------v--------------+
                  |  Счетчик (CNT, 16/32 бита)   | <----+
                  +--------------|--------------+      |
                                 |                      | Reset
                  +--------------v--------------+      |
                  | Автоперезагрузка (ARR)      | -----+
                  +-----------------------------+
                                 |
                                 v Событие обновления (Update Event / UIF)
```

1. **Регистр предделителя `PSC` (Prescaler):** 16-битный делитель частоты входного тактового сигнала. Позволяет понизить входную частоту в $(PSC + 1)$ раз.
2. **Регистр счетчика `CNT` (Counter):** Текущее значение счетчика, инкрементируемое (или декрементируемое) на каждом импульсе после предделителя.
3. **Регистр автоперезагрузки `ARR` (Auto-Reload Register):** Задает пороговое значение счета. По достижении значения `ARR` счетчик сбрасывается в ноль, и генерируется событие обновления (**Update Event, флаг UIF**).

### 7.2. Формула расчёта частоты переполнения и временных квантов
* Частота счета таймера:
  $$f_{CNT} = \frac{f_{CK\_PSC}}{PSC + 1}$$
* Период генерации прерывания обновления (период переполнения):
  $$T_{Update} = \frac{(PSC + 1) \times (ARR + 1)}{f_{CK\_PSC}}$$
* Частота прерываний:
  $$f_{Update} = \frac{1}{T_{Update}} = \frac{f_{CK\_PSC}}{(PSC + 1) \times (ARR + 1)}$$

> **Пример:** Требуется настроить таймер на прерывания строго каждые $1\text{ мс}$ ($1000\text{ Гц}$) при тактовой частоте $f_{CK\_PSC} = 84\text{ МГц}$.  
> Выбираем $PSC = 83$ (делитель $83 + 1 = 84$). Тогда частота счета $f_{CNT} = \frac{84\text{ МГц}}{84} = 1\text{ МГц}$ (шаг 1 мкс).  
> Тогда для периода 1000 мкс задаем $ARR = 1000 - 1 = 999$.

### 7.3. Режимы работы: периодические прерывания, ШИМ (PWM), захват
* **Периодический таймер (Time Base):** генерация прерываний по переполнению для отсчета временных интервалов и системных тиков.
* **Широтно-импульсная модуляция (PWM / ШИМ):** сравнение значения счетчика `CNT` со значением регистра захвата/сравнения `CCR` (Capture/Compare Register). Пока $CNT < CCR$, на ножке МК держится высокий уровень; при $CNT \ge CCR$ — низкий уровень. Позволяет плавно регулировать яркость светодиодов или управлять пьезодинамиком стенда (PE9, TIM1_CH1).
* **Входной захват (Input Capture):** измерение длительности импульсов внешних сигналов.

### 7.4. Роль таймеров при работе с I2C, таймаутами и частотой обновления кадров (FPS)
1. **Предотвращение зависания шины I2C (Bus Lockup Timeout):**
   Если ведомое устройство сбоит и бесконечно удерживает линию SCL или SDA в нуле, микроконтроллер рискует зависнуть в цикле ожидания. Системный таймер `SysTick` (функция `HAL_GetTick()`) обеспечивает жесткий контроль времени ожидания: если за заданный таймаут (например, 100 мс) флаг не поднялся, функция принудительно возвращает `HAL_TIMEOUT` и инициирует программный сброс шины битом `SWRST`.
2. **Квантование времени пользовательского интерфейса (FPS):**
   Для плавного вывода изображения и исключения мерцания экран не должен обновляться чаще 20–30 раз в секунду. Таймер отсчитывает интервалы между отрисовками кадров (например, 50 мс для 20 кадров/с).
3. **Отсчёт таймаутов кодового замка:**
   Отсчёт 10 секунд бездействия до автоматического сброса ввода, 3 секунд удержания открытого замка и 5 секунд аварийной блокировки.

## 8. Архитектура программно-аппаратного комплекса (Вариант № 5)

### 8.1. Конечный автомат кодового замка (FSM)

```
             +---------------------------------------+
             |                                       | Таймаут 10 с
             v                                       |
    +------------------+  Неверный код (1-я, 2-я)    |
    |  LOCK_LOCKED     | ------------------------+   |
    | (Дежурный режим) | <--------------------+  |   |
    +--------|---------+                      |  |   |
             |                                |  |   |
             | Верный пароль                  |  |   |
             v                                |  v   |
    +------------------+             +-------------------+
    |  LOCK_UNLOCKED   |             |    LOCK_ERROR     |
    | (Открыт на 3 с)  |             | (Красная вспышка) |
    +--------|---------+             +---------|---------+
             |                                 |
             | Истекли 3 с                     | 3 ошибки подряд
             +------------------->+            v
                                  |   +-------------------+
                                  |   |   LOCK_BLOCKED    |
                                  |   | (Блокировка на 5 с|
                                  |   +---------|---------+
                                  |             | Истекли 5 с
                                  +------------>+
```

* **Дежурный режим (`LOCK_STATE_LOCKED`):** Замок ожидает ввода символов. На OLED выводится баннер замка и маска ввода (`DISPLAY:____`). Контролируется таймаут бездействия: если после ввода первого символа пауза превышает 10 секунд, введенная строка обнуляется.
* **Состояние доступа (`LOCK_STATE_UNLOCKED`):** Достигается при совпадении всей введенной строки с активным мастер-паролем. На OLED выводится `>> OPENED! << / ACCESS OK`, на 3 секунды включается зеленый светодиод VD6 (PD13). В порт передается `STATUS:OK`.
* **Состояние ошибки (`LOCK_STATE_ERROR`):** Неверный код вызывает одиночную вспышку красного светодиода VD7 (PD15), инкремент счетчика ошибок и отправку `STATUS:ERR`.
* **Состояние блокировки (`LOCK_STATE_BLOCKED`):** При достижении 3 ошибок подряд замок блокируется на 5 секунд. Красный светодиод циклически мигает, на дисплее горит `>> ERROR! << / BLOCKED`, в порт передается `STATUS:BLOCKED`. Все попытки ввода игнорируются до истечения таймера.

### 8.2. Текстовый протокол взаимодействия ПК и стенда по UART

| Пакет (TX / RX) | Формат строки | Описание и реакция сторон |
|---|---|---|
| **ПК $\rightarrow$ Стенд** | `PING\n` | Проверка связи при старте программы на ПК. |
| **Стенд $\rightarrow$ ПК** | `PONG\n` | Ответ микроконтроллера о готовности к работе. |
| **ПК $\rightarrow$ Стенд** | `AUTH:<password>\n` | Попытка авторизации введенным в GUI паролем. |
| **Стенд $\rightarrow$ ПК** | `STATUS:OK\n` | Доступ разрешен: замок открыт на 3 с. |
| **Стенд $\rightarrow$ ПК** | `STATUS:ERR\n` | Ошибка: неверный пароль. |
| **Стенд $\rightarrow$ ПК** | `STATUS:BLOCKED\n`| Превышен лимит ошибок: замок заблокирован на 5 с. |
| **ПК $\rightarrow$ Стенд** | `SET:<new_password>\n`| Команда прошивки нового мастер-пароля в EEPROM. |
| **Стенд $\rightarrow$ ПК** | `STATUS:SAVED\n` | Новый пароль успешно записан в память MCP79411. |
| **Стенд $\rightarrow$ ПК** | `DISPLAY:<string>\n` | Трансляция текущего текста OLED-экрана на ПК. |

### 8.3. Клиентское приложение на Python / Tkinter: многопоточность и логгер
Приложение построено по двухпоточной модели:
1. **Главный поток (GUI Thread):** Обрабатывает оконные события библиотеки `tkinter`, реагирует на нажатия кнопок («Открыть замок», «Записать в EEPROM», «Сброс»), управляет цветом визуального баннера статуса.
2. **Фоновый поток (Worker Thread):** Непрерывно слушает входящий поток байт от COM-порта через библиотеку `pyserial`. Когда приходит завершающий символ `\n`, строка декодируется и передается в очередь событий GUI. Это полностью исключает зависание интерфейса программы при ожидании ответа от стенда.
3. **Логирование сеансов:** Каждый принятый и отправленный пакет немедленно записывается в файл `uart_session_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.log` с точностью до миллисекунды:
   ```text
   [2026-10-23 17:42:41.042] [TX] AUTH:1234
   [2026-10-23 17:42:41.195] [RX] STATUS:OK
   [2026-10-23 17:42:41.227] [RX] DISPLAY:OPENED
   ```

## 9. Шпаргалка: Топ-15 каверзных вопросов преподавателя на защите

### В1: Почему линии SCL и SDA обязательно требуют внешних подтягивающих резисторов?
> **Ответ:** Выходные каскады всех устройств на шине I2C выполнены по схеме с открытым стоком (Open-Drain). Устройства могут лишь притягивать линию к земле (уровень LOW). Формирование высокого логического уровня (HIGH) осуществляется исключительно внешними подтягивающими резисторами при закрытых транзисторах всех устройств. Это предотвращает короткие замыкания при одновременной встречной передаче и обеспечивает аппаратный арбитраж шины.

### В2: Как разрешаются коллизии, если два ведущих устройства одновременно начинают передачу?
> **Ответ:** За счет логики монтажного «И». Каждый передатчик во время передачи своего бита одновременно считывает реальное состояние линии SDA. Если передатчик отпустил линию (передает $1$), но считал с шины $0$ (так как другой передатчик притянул линию к земле), он фиксирует потерю арбитража (флаг `ARLO` в регистре `SR1`), мгновенно выключает передачу данных и ждет освобождения шины условием STOP.

### В3: Какой 7-битный и 8-битный адрес имеет OLED-контроллер SSD1306 на стенде SDK-1.1M?
> **Ответ:** 7-битный адрес равен `0x3C`. При передаче по шине адрес сдвигается на 1 бит влево, а младший 0-й бит указывает направление ($0$ — запись, $1$ — чтение). Таким образом, 8-битный адрес записи равен $0x3C \ll 1 = 0x78$, а адрес чтения — $0x79$.

### В4: Какой адрес на шине имеет микросхема памяти EEPROM MCP79411?
> **Ответ:** Микросхема MCP79411 объединяет два независимых функциональных узла: часы реального времени RTC (7-битный адрес `0x6F`, 8-битный `0xDE`) и энергонезависимую память EEPROM (7-битный адрес `0x57`, 8-битный адрес записи `0xAE`).

### В5: Зачем после записи каждого байта в память EEPROM в прошивке выдерживается задержка 5-6 мс?
> **Ответ:** Запись в ячейки EEPROM основана на физическом эффекте туннелирования электронов в плавающий затвор через слой диэлектрика (высоковольтный цикл стирания/записи). Этот внутренний процесс микросхемы занимает технологическое время $t_{WC} \le 5\text{ мс}$. В течение этого времени микросхема занята и не отвечает на запросы по шине I2C (выдает NACK). Без выдержки паузы следующие отправленные байты будут потеряны.

### В6: Как организована видеопамять GDDRAM дисплея SSD1306?
> **Ответ:** Видеопамять имеет размер 1024 байта и организована в виде 8 страниц (Page 0 .. Page 7) по 128 столбцов каждая. Байт кодирует вертикальный столбец из 8 пикселей: младший бит $D_0$ соответствует верхнему пикселю страницы, а старший $D_7$ — нижнему.

### В7: Почему передача кадра дисплея по I2C может заблокировать другие задачи и как с этим бороться?
> **Ответ:** Полный кадровый буфер занимает 1024 байта. На стандартной частоте шины 100 кГц передача такого массива занимает около $100\text{ мс}$, в течение которых шина I2C полностью занята. Чтобы другие устройства (клавиатура, память) не блокировались, передачу кадра либо разбивают на кванты, либо выполняют через DMA, либо в ОС РВ защищают доступ к шине мьютексом.

### В8: Что произойдет с паролем при полном отключении питания стенда и почему?
> **Ответ:** Пароль останется полностью сохранным. Ячейки памяти EEPROM хранят заряд на изолированном диэлектриком плавающем затворе, который сохраняет электроны без подачи внешнего напряжения более 100 лет. При повторном включении прошивка считывает пароль из ячеек `0x00 .. 0x11` микросхемы MCP79411.

### В9: Зачем клиентская программа при подключении к порту сразу отправляет команду PING?
> **Ответ:** По требованию методических указаний команда `PING` выполняет автоматическую валидацию подключения: она проверяет, что выбран правильный COM-порт, отладочный мост FTDI исправен, микроконтроллер включен, прошивка запущена и готова принимать прикладные команды авторизации.

### В10: В чём отличие горизонтального режима адресации SSD1306 от постраничного?
> **Ответ:** В постраничном режиме (Page Addressing) по достижении правого края экрана (127-го столбца) счетчик зацикливается на начало той же страницы. В горизонтальном режиме (Horizontal Addressing) счетчик автоматически переходит на нулевой столбец следующей страницы ($Page_n \rightarrow Page_{n+1}$), что позволяет передать весь фреймбуфер экрана (1024 байта) за одну непрерывную транзакцию.

### В11: Что такое Clock Stretching в интерфейсе I2C?
> **Ответ:** Это аппаратный механизм управления потоком данных со стороны ведомого устройства. Если ведомый не успевает обработать принятый байт, он принудительно притягивает линию SCL к нулю. Ведущий узел аппаратно видит низкий уровень на SCL и приостанавливает передачу до тех пор, пока ведомый не освободит линию.

### В12: Как рассчитывается значение регистра I2C_CCR в STM32 для Standard Mode (100 кГц)?
> **Ответ:** В стандартном режиме период $T_{SCL} = 10\text{ мкс}$, из которых высокий уровень $T_{high} = 5\text{ мкс}$. Значение $CCR$ равно числу тактов шины APB1 за время $T_{high}$: $CCR = \frac{T_{high}}{T_{PCLK1}}$. При частоте шины APB1 42 МГц ($T_{PCLK1} \approx 23.8\text{ нс}$) получаем $CCR = \frac{5000\text{ нс}}{23.81\text{ нс}} \approx 210$ (`0xD2`).

### В13: Какую функцию выполняет регистр I2C_TRISE?
> **Ответ:** Регистр `TRISE` задает максимально допустимое время нарастания фронта сигнала на линиях SCL и SDA с учетом тактовой частоты шины APB1. Для Standard Mode максимальное время нарастания равно 1000 нс, поэтому $TRISE = \frac{1000\text{ нс}}{T_{PCLK1}} + 1$. Контроллер использует это значение для компенсации емкостной задержки нарастания напряжения через резисторы подтяжки.

### В14: Зачем в прошивке нужен локальный массив SSD1306_Buffer[1024], если у дисплея есть собственная память GDDRAM?
> **Ответ:** Контроллер дисплея SSD1306 по шине I2C не поддерживает выборочное чтение отдельных битов. Чтобы изменить всего один пиксель $(x, y)$, не нарушив соседние 7 пикселей в том же вертикальном байте, необходимо иметь полную копию видеопамяти в ОЗУ микроконтроллера, выполнить побитовые операции `OR`/`AND` в памяти, а затем обновить экран.

### В15: Как в клиентском приложении на Python предотвращается зависание GUI при чтении данных из COM-порта?
> **Ответ:** За счет многопоточной архитектуры. Опрос последовательного порта и чтение байт функцией `serial.readline()` вынесены в отдельный фоновый поток (Worker Thread). Основной поток программы (GUI Thread) остается полностью отзывчивым к действиям пользователя и графическим событиям.
